# blocksctl 0.1.0

The first release provides a terminal workflow for compiling Littlefoot source and loading it onto a Lightpad BLOCK. It reuses the public ROLI SDK and runs without the ROLI desktop apps or a vendor service.

The binary targets Apple Silicon `arm64` and requires macOS 15.0 or later. It needs no local compiler or Xcode installation. This release includes no prebuilt Intel Mac or Linux executable; source builds are available.

The binary archive includes the executable, `INSTALL.md`, distribution terms, licence texts, dependency notices and `BUILD-INFO.json`. The executable is ad-hoc signed, without Developer ID signing or Apple notarization. The install guide covers verification and macOS's per-item approval.

## Commands

| Command | Behaviour |
| --- | --- |
| `compile SOURCE -o OUTPUT` | Offline compilation to a raw binary or C++ header. No device access. |
| `devices --timeout SECONDS` | Active SDK discovery with device serials, firmware and transport. |
| `upload SOURCE --device SERIAL` | Temporary upload, with the session held open until Ctrl-C or device loss. |
| `save-default SOURCE --device SERIAL` | Upload and save request that replaces the device's startup default. Verify it after a full power cycle. |

Compilation and upload use the same 512-byte default heap. A source `#heapsize: N` directive overrides it. Device timeouts bound discovery and transfer; a loaded temporary session stays open.

## Verification

The release packages the exact executable built from source revision `61f792060926d6773242bb02caf2a0adf724c2a8`. Later changes add documentation, packaging and licence notices; the compiled source and build inputs are unchanged. Its SHA-256 is `6d6e9ff9ba33205ab839fb0f9ad8a927b750d03436d2c0ebfae922dc708249e4`.

- Native builds and eight offline tests passed on macOS 15 Apple Silicon and Ubuntu 24.04 x86-64. The Mac executable also passed those tests on an Apple Silicon Mac running macOS 27.2.
- With a matching source heap directive, one program compiled to the same 2,954-byte payload as the independent BLOCKS Code reference, byte for byte.
- On one Lightpad with firmware 1.1.0, USB and Bluetooth discovery and temporary upload passed with physical light, touch and MIDI checks.
- Ctrl-C ended the temporary session and returned to the saved default. Disconnects after transfer ended the old process; explicit discovery and upload after reconnect succeeded on both transports.
- Saving a distinct default and restoring the prior baseline both passed full power-cycle and physical/MIDI checks over USB.

Details and evidence boundaries are recorded in [offline verification](../verification/2026-11-06.md), [USB QA](../verification/2026-11-06-usb-hardware.md) and [Bluetooth, recovery and persistence QA](../verification/2026-11-06-device-lifecycle.md).

## Limits

Hardware checks cover one Lightpad, firmware 1.1.0, on macOS. Other models, firmware versions, Linux hardware, disconnect during transfer, lock contention and long-duration reliability remain unverified. The tests closed ROLI applications; they did not test a clean host with all ROLI software uninstalled.

The SDK provides no flash-save acknowledgement. The persistence checks used full power cycles and observed device behaviour, rather than treating the save request as proof. blocksctl does not export an unknown saved program, update firmware or provide the BLOCKS Code editor's project and parameter UI.
